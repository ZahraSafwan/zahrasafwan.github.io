كيف تراجع وكيل الذكاء الاصطناعي (AI Agent)؟

دليل عملي بلغة مبسّطة للمراجع الداخلي: ماذا يطلب؟ ماذا يختبر؟ ما المخاطر؟ وما الملاحظات والتوصيات التي قد تظهر أثناء المراجعة؟

الفكرة الأساسية: لا تبدأ بمراجعة النموذج نفسه. ابدأ بفهم ما الذي يفعله الوكيل داخل العملية، وما البيانات والأنظمة التي يصل إليها، وما القرارات أو الإجراءات التي يستطيع تنفيذها.

🧩 سيناريو مبسّط: وكيل لمعالجة طلبات استرداد المبالغ

تستخدم شركة وكيل ذكاء اصطناعي لمراجعة طلبات استرداد العملاء. يقرأ بيانات الطلب وسجل العميل، يقترح القرار، وقد ينفذ الاسترداد تلقائيًا إذا كانت العملية ضمن الحدود المسموح بها.

خريطة المراجعة في خمس خطوات

1افهم العمليةحدد دور الوكيل وبداية ونهاية مسؤوليته.
2اطلب الأدلةالسياسات، الإعدادات، الصلاحيات، السجلات والاختبارات.
3اختبر الضوابطلا تكتفِ بوجودها على الورق.
4قيّم المخاطرما الذي قد يحدث عند الخطأ أو التلاعب؟
5اكتب النتيجةملاحظة واضحة وتوصية قابلة للتنفيذ.

1. ماذا يطلب المراجع قبل بدء الاختبار؟

ابدأ بما يساعدك على فهم الوكيل وحدوده وطريقة تشغيله.

01وصف الوكيل والغرض منهالمالك، الهدف، العمليات التي يدعمها، وما لا يُسمح له بفعله.
02مخطط سير العمليةمن الإدخال إلى القرار والتنفيذ، مع الأنظمة والأطراف المتداخلة.
03قائمة الأنظمة والأدواتCRM، البريد، قواعد البيانات، APIs وأي أدوات متصلة.
04مصفوفة الصلاحياتما الذي تستطيع هوية الوكيل قراءته أو تعديله أو حذفه؟
05قواعد الموافقة البشريةما العمليات التي تتطلب موافقة؟ وكيف يمنع النظام التنفيذ قبلها؟
06السجلات والتنبيهاتالقرارات، Tool Calls، الموافقات، التنفيذ والتنبيهات الأمنية.
07إدارة التغييراتتغييرات النموذج والـPrompts والأدوات والصلاحيات ونتائج اختبارها.
08الحوادث والاختبارات السابقةالمشكلات المعروفة، الاختبارات الأمنية، وخطط المعالجة.

2. ما أهم ما يراجعه المراجع؟

01

النطاق والمسؤولية

هل الغرض واضح؟ وهل يوجد مالك مسؤول وحدود لما يستطيع الوكيل فعله؟

اختبار عمليقارن الوثائق بما يستطيع الوكيل فعله فعليًا داخل الأدوات المتصلة.
02

البيانات

ما البيانات التي يدخل إليها؟ وهل يحتاجها؟ وهل تحتوي على بيانات حساسة أو شخصية؟

اختبار عمليتتبّع عينة من البيانات من المصدر إلى الوكيل ثم إلى النتيجة أو السجل.
03

الصلاحيات والوصول

هل يملك أقل قدر من الصلاحيات اللازمة، أم يستطيع استخدام أدوات أو إجراءات لا يحتاجها؟

اختبار عمليراجع هوية الوكيل وصلاحياتها، واختبر في بيئة آمنة إجراءً خارج النطاق.
04

القرار

هل يقدم توصية أم يتخذ القرار؟ وما البيانات أو القواعد التي يعتمد عليها؟

اختبار عملياختبر حالات عادية وحدودية واستثناءات، وقارن النتيجة بالقرار المتوقع.
05

الموافقة البشرية

هل العمليات عالية الأثر تتوقف فعليًا، أم أن التوقف مجرد تعليمات داخل الـPrompt؟

اختبار عمليحاول الوصول إلى التنفيذ دون موافقة وتأكد أن النظام يمنع العملية تقنيًا.
06

التنفيذ

هل يستطيع تنفيذ عمليات حساسة أو غير قابلة للتراجع؟ وهل توجد حدود وإمكانية للإيقاف؟

اختبار عمليراجع حدود التنفيذ، آلية الإيقاف، والاسترجاع أو التراجع عندما يكون ذلك ممكنًا.
07

السجلات والمراقبة

هل تستطيع إعادة بناء المهمة والقرار والأدوات والموافقة والنتيجة؟

اختبار عملياختر عملية مكتملة وحاول إعادة بنائها من البداية إلى النهاية باستخدام السجلات فقط.
08

التغيير والاختبار الأمني

ماذا يحدث بعد تحديث النموذج أو الـPrompt أو إضافة أداة جديدة؟

اختبار عملياختر تغييرًا حديثًا وتحقق من الموافقة والاختبار قبل الاستخدام الفعلي.

3. ما المخاطر التي تبحث عنها؟

مرتفع

تنفيذ إجراء غير مصرح به

حذف أو تحويل أو إرسال أو تغيير صلاحيات دون موافقة مناسبة.

مرتفع

وصول أوسع من الحاجة

صلاحيات تسمح بالوصول إلى بيانات أو أدوات خارج نطاق المهمة.

متوسط

قرار غير صحيح

قرار خاطئ أو غير متسق يؤثر في العميل أو العملية.

متوسط

ضعف التتبع

سجلات غير كافية لإثبات كيف تم القرار أو التنفيذ.

متوسط

تسرب البيانات

ظهور بيانات حساسة في السياق أو السجلات أو خدمات خارجية.

راقب

تغييرات غير مضبوطة

تغيير Prompt أو أداة أو نموذج دون اختبار أو موافقة مناسبة.

4. أمثلة على ملاحظات قد يكتشفها المراجع

ما لاحظه المراجعلماذا يهم؟التوصية المحتملة
الموافقة البشرية موجودة في الـPrompt فقط.قد يتم تجاوز التعليمات أو تفسيرها بطريقة غير متوقعة.فرض Approval Gate تقني مستقل قبل العمليات عالية الأثر.
الوكيل يملك صلاحية حذف رغم أن عمله يحتاج القراءة فقط.يزداد أثر أي خطأ أو استغلال.تطبيق أقل قدر من الصلاحيات وإزالة الوصول غير المطلوب.
لا يمكن ربط القرار بالبيانات أو الأداة التي استخدمها الوكيل.يصعب التحقيق في الخطأ أو إثبات فعالية الضابط.توسيع سجل التدقيق ليشمل القرار والأدوات والموافقات والنتيجة.
إضافة أداة جديدة دون إعادة اختبار.قد تتوسع الصلاحيات أو يتغير مسار المخاطر.إخضاع أدوات الوكيل لإدارة التغيير واختبار ما قبل الإنتاج.
التنبيه يصل، لكن لا توجد آلية واضحة للتصعيد.الاكتشاف دون استجابة قد لا يمنع الضرر.تحديد المسؤول وزمن الاستجابة ومسار التصعيد واختباره دوريًا.

5. كيف تكتب ملاحظة واضحة؟

الحالة: الوكيل يستطيع تنفيذ استرداد مالي مرتفع القيمة دون بوابة موافقة تقنية قبل التنفيذ.

الخطر / الأثر: قد يؤدي قرار خاطئ أو التلاعب بالوكيل إلى تنفيذ عملية مالية غير مصرح بها، مما قد يسبب خسائر مالية أو عمليات استرداد غير صحيحة.

السبب: الاعتماد على تعليمات الوكيل أو قواعد داخل الـPrompt لطلب الموافقة، دون وجود ضابط تقني في الـWorkflow يمنع تنفيذ العمليات عالية الخطورة قبل الحصول على موافقة بشرية.

التوصية: تصنيف عمليات الاسترداد حسب مستوى الخطورة، وفرض بوابة موافقة بشرية تقنية للعمليات عالية الأثر، بحيث لا يستطيع الوكيل تنفيذ العملية قبل تسجيل الموافقة.

6. كيف تبدو البيئة الجيدة؟

✓ الغرض والمالك والنطاق موثقون
✓ صلاحيات الوكيل محدودة حسب الحاجة
✓ العمليات عالية الأثر لها موافقة بشرية حقيقية
✓ القرارات والإجراءات قابلة للتتبع
✓ توجد مراقبة وتنبيهات واستجابة
✓ التغييرات المهمة يعاد اختبارها قبل الإنتاج
✓ توجد آلية إيقاف أو سحب وصول
✓ يتم اختبار الحالات العادية والحدودية والسلبية
